Heroes Awakening — Reimagine Review

Three reimagined drafts of heroes-awakening.html compared against the live page and the underlying game-data audit. Findings, calculator coverage, and a prioritized migration path into production.

1. TL;DR

  1. The production page is numerically wrong on its two biggest claims: skill stone cost (off by ~30×, real cost is 75–650 stones / level, not 2–10) and 40-level cumulative totals (row 40 still shows L39 numbers; true totals are 1,140 Hero Shards + 740 ES chips). All three drafts fix both.
  2. All three drafts surface the Honor Wall (200 sub-levels × 2 sub-tracks = 39,900 stones / +40,000 FP per hero) — the single largest gap on the live page, which currently misstates it as "100 sub-levels per skill".
  3. V2 is the most audit-accurate spreadsheet, with 6 first-class tools (Stones → Target, Awake 0 → 40, Team FP, Combo Trio, Compare, Honor Wall) and explicit "Audit fix" notes — but it is the most hostile to a brand-new player: small spinners, a meme-gate before any content, and silent state resets on hero switch.
  4. V3 is the friendliest on-ramp (decision tree → priority strip → checklist → 3 calculators) but ships with a broken stones calculator (off-by-one against the audit ladder), a default type-mismatch swap that loads BLOCKED, and a dead "skill slot" field — exactly the kind of misinformation a Start-Here page can't afford.
  5. V4 is the most distinctive visually (cinematic portraits, combo trio gallery, ownership state in localStorage) but bets its core "awakening" moment on :hover, exposes table-name internals in player copy, picks the wrong skill description string at Lv 6+, and ships a dead Honor Wall sub-track selector. Recommended pick: merge V2's calculators + V3's funnel structure into the production page; pull V4's combo-trio gallery and owned-hero localStorage as polish.

  • Per skill: 2,250 stones max → 9,000 / hero (4 skills) → 54,000 stones to fully skill the 6 Phase I anchors.
  • Each skill level = +3,000 hero FP and +859.4 team FP (max 8,594 / skill, 34,376 across 4).

Honor Wall — the missing endgame

After all 4 skills are at Lv. 10, each hero unlocks a Honor Wall extension (hero_awakening_maxUpgrade): 2 sub-tracks × 200 levels each.

  • Stone cost cliff: 50 stones L1–50 → 80 L51–100 → 120 L101–150 → 150 L151–199 → 0 at L200.
  • Per sub-track total: 19,950 stones → full Honor Wall = 39,900 stones / hero.
  • Adds +100 FP per sub-level → +40,000 FP / hero on top of skills and ladder.
  • True per-hero max FP: 80,000 (ladder) + 4 × 30,000 (skills) + 40,000 (Honor Wall) = +240,000.

The production page mentions this as "100 sub-levels per skill" with the wrong shape (it's 200 × 2, not 100 × 4) and never surfaces a stone cost.

Hero Swap

  • 24 donors (8 Army / 8 Navy / 8 Air) → 18 awakening targets in 3 type-locked pools.
  • Irreversible. Once per target per phase. Type must match.
  • Donor is not deleted — it resets to 1★ Lv. 1 and stays in roster. Donor's 10 unlock-shards stay on the donor.
  • 100% of donor's upgrade materials convert to target shards / ES chips. Talents are a two-way swap. The swap itself is free.
  • Ineligible donors: heroes whose only upgrade material is Hero EXP; heroes currently on a march / task.

3. Current page assessment

Findings drawn from AUDIT.json.currentPageAudit. Each item is grounded against the production page section it appears in.

Strengths

  • Hero data is correct. All 18 IDs, the 3-phase grouping, and the 6 awakened persona labels (Sara=Saboteur, Nova=Astral Flame, Shen Suyu=Flame Maiden, Lophy=Neon Shark, Carna=Herald of Thunder, Jett=Silverwing) match hero_awakening_hero and hero_awake_labelNNN exactly.
  • Combo trios are accurate. Anchor + 2 partners for all 6 trios match skill_NNN_301 lang strings.
  • Awakening prerequisite copy "5★ · Lv. 120 · Exclusive Skill Lv. 5" matches the in-game tooltip (hero_awake_exchangeactivity_95).
  • Hero Swap copy is comprehensive: all 43 tooltips (hero_awake_exchangeactivity_1-101) are surfaced verbatim with their lang keys.
  • Awakening Time event mechanics (1 chest immediately, 6 over 7-day cadences) match the unlock-activity lang.

Inaccuracies (numerical)

  • Skill stone cost is ~30× under. Page says "2–10 Awakening Stones per skill level" and lists per-pull as 2/2/4/4/6/6/8/12/20. Real is 15/15/30/30/45/45/60/80/130 per pull (5 pulls / level), 2,250 stones to max one skill.
  • Stones to max a hero never surfaced. Correct value is 9,000 / hero; 54,000 for all 6 Phase I.
  • 40-level cumulative totals are wrong. levelTable row 40 still shows cumulativeMainStones=1090, cumulativeSubStones=700 — identical to row 39. Correct: 1,140 / 740. Summary copy "roughly 1,000 Hero Shards + 700 ES Skill chips" repeats the same understatement.
  • Tier 4 bucket is off-by-one. levelTable.tiers[3] says levels 30–39, count 10. Real: 30–40, count 11, with 550 shards / 440 chips for the tier (not 500 / 400).
  • ES7 buff swap pattern has wrong digits. Page says 21x101 → 21x1101 (literally the same string on both sides). Real: 7-digit buff IDs, digit 3 flips 0→1 (Sara 2201101 → 2211101, Nova 2101101 → 2111101).
  • Max FP claim is partial. Page advertises "+80,000 Fight Power"; that is the 40-level ladder alone. With 4 maxed skills (+120,000) and Honor Wall (+40,000), real per-hero ceiling is +240,000 FP.
  • Honor Wall shape is wrong. Footer note says "100 sub-levels per skill" — it is 200 × 2 sub-tracks, total 7,200 rows in maxUpgrade (= 18 heroes × 400).

Gaps (missing from page)

  • Honor Wall extension and its stone cost (39,900 / hero).
  • True per-hero stone budget to max all 4 skills (9,000) and the Phase I total (54,000).
  • Stone-cost ladder per skill level as a real table — only summary text exists today.
  • Phase II/III awakening card IDs (44300007–44300018) as "Coming Soon" rows with hero pairings.
  • ES7 buff-family swap table for all 6 Phase I × 4 skills = 24 mappings.
  • skill_team_fight_pewer — secondary team-FP column (8,594 / skill at L10, 34,376 across 4).
  • Per-level dual-buff structure clarification (L6+ need_add_buff becomes a pipe pair) — currently conflated with the ES7 swap.
  • Cross-link between Hero Swap targets and combo trios — Phase II/III targets exist in hero_exchange.get_hero but the swap UI never shows them.

UX issues

  • Awakening tab is overloaded: 15+ sections, 5 tables, 3 large grids.
  • Rough-numbers phrasing ("roughly 1,000 Hero Shards") in a planning page — players need exact numbers.
  • No calculators. Page is purely informational despite carrying all the inputs.
  • Phase II/III tiles are blank placeholders even where the lang pack has bios (e.g. Ella).
  • Hero Swap is a static donor → target picker with no ROI signal and no current-state input.
  • ES7 buff swap is described in dense buff-ID language a player can't act on.
  • Level-cost table column reads "Gold Shard" — a label that doesn't exist in-game (it's Hero Shard).
  • "Grand Slam" tab tag says "stones"; "Spotlights & History" tab buries the Discord timeline + Q&A.
  • No side-by-side hero compare ("show me all Lv. 10 skill 1 effects side by side").
  • Awakening Cards grid has no integration with player identity — no signal of which have been used.

4. Three reimagined versions

Each draft is a single self-contained HTML file under landing-page/pages/experiments/. Iframes load the local file directly.

V2

Stat Spreadsheet

Bloomberg-style power-user terminal · 6 first-class tools
v2-stat-spreadsheet.html · 1,836 lines Open in new tab ↗ View source

Pillar bullets

  • Pinned appbar + sticky hero bar (hero / phase / stones-max counters always visible).
  • 5 numbered sections: Summary · Skill Explorer · Calculator Toolbox · Reference Tables · Hero Swap.
  • Calculator Toolbox tabs through 6 tools side-by-side.
  • 13px mono "terminal" voice; tabular numbers + delta cells throughout.
  • Inline green "Audit fix" call-outs that explicitly contrast V2 against the live page.

Calculators implemented

  • Stones → Target per skill with 4-skill aggregate
  • Awake 0 → 40 shard + chip + tier breakdown
  • Team FP delta per skill
  • Combo Trio planner (single global level — see issue below)
  • Compare A/B + level segmented control 1/3/5/7/9/10
  • Honor Wall per sub-track stone cost + FP gain

Strengths

  • Numbers line up with the audit: STONE_PER_LEVEL, STONE_PER_PULL, STONES_MAX_ONE_HERO=9000, STONES_MAX_PHASE_I=54000, FP_PER_SKILL_LEVEL=3000, TFP_AT_L10=8594, Tier IV count:11, shardTier:550, chipTier:440 all match.
  • Honor Wall is first-class — 50/80/120/150 cliff, 19,950 / sub-track, 39,900 total, +40,000 FP per hero — verbatim from the audit.
  • Audit fixes are explicit, not silent: tier IV = 11 levels and the correct ES7 7-digit pattern (2201101 → 2211101) are called out next to the wrong live-page string.
  • Skill Explorer lets you click a row to seed the stones calculator; description switches L1 / L2–5 / L6+ to reflect the real string ladder.
  • Compare tool is genuinely useful — exactly the "all Lv. 10 skill 1 effects side by side" gap the audit calls out.

Accuracy issues

  • Hero-summary "quickstats" mislabels: the third value says "+ honor wall" but actually holds the all-in 240,000 figure. Math right, label wrong.
  • Combo Trio tier label is 'tier '+(tierIdx+1)+' of 10' — silently picks the 4-level scaling. The audit summary itself is self-contradictory ("every 5 levels" vs "every 4 levels"); flag rather than silently pick.
  • Combo Trio member ordering is hard-coded P1/P3/P2; works today only because every members[] entry happens to be in that order. Fragile if JSON shifts.
  • Trio label uses the local COMBO_TRIOS constant (abbreviated "Regular Atk", "Active Skill DMG / Abnormal Status") instead of the audit's canonical comboLabel / buffName.
  • ES Skill Chip helper text shows fallback 38003xxx placeholder for Phase II/III heroes even though the audit already carries their real IDs (Marvingt 38003191, Rohr 38003381, etc.).

UX issues

  • Hostile entry gate. "Verification required" modal with three buttons (fk boats / tanks / planes) — wrong choices POST to the rickroll counter and redirect to passwords.html. A new visitor can't get past the in-group meme.
  • Hero switch silently destroys input in Stones → Target (STATE.stonesCurrent / stonesTarget reset) while the other 5 tools persist; inconsistent and undoable.
  • Tap targets are brutal on mobile: ± spinner buttons are 24 × 28 px — well under WCAG 44 × 44.
  • Hero strip is one horizontally-scrolling row of 18 chips with no type filter or search.
  • Calculator Toolbox tab badges update for 3 tools and stay blank for 2 — looks broken.
  • Picker modal auto-fills new combo slots with awakeLv:40, skLv:40 — fully-maxed default with no explanation.
  • Honor Wall sub-track segmented control (Track 1 / Track 2) is cosmetic — honorCostFor() never reads STATE.honorSub.
  • Hero Swap donor cards are uniform tiles with no per-donor signal (cost converted, investment, talent count, ES7 status).
  • Compare tool dropdowns exclude Phase II/III heroes; the hero strip lets you pick them, the Compare tool silently doesn't.
  • Combo planner uses one global level spinner for all 3 trio members; reality is independent levels per member.
  • "Audit fix" notes assume the reader has already seen the live page — no link or screenshot reference.

Verdict

  • Technically excellent, audit-accurate power-user spreadsheet that nails every number the audit exposes — but ships behind a meme-gate, mislabels its own headline FP figure, hides one tool's state behind a no-op toggle, and is rough on mobile. Great for Tex; rough for any cold visitor.
V3

Player Journey

4-step "Start Here" funnel · decision tree + saved checklist
v3-player-journey.html · 1,630 lines Open in new tab ↗ View source

Pillar bullets

  • 4-step funnel: Decision tree → Priority strip → Saved checklist → 3 live calculators.
  • Sticky priority-pill strip re-scores 6 Phase I cards by player answers.
  • 5-item checklist persisted to localStorage with a progress bar.
  • Graceful icon fallback: CDN → local asset → 2-letter monogram tile.
  • Honest currency split: stones → skills, per-hero shards + ES chips → 40-level ladder.

Calculators implemented

  • Stones → Target per skill broken (off-by-one)
  • Awake 0 → 40 shard + chip budget correct
  • Swap vs grind ROI type-locked, irreversible, talent transfer notes default BLOCKED
  • Honor Wall — mentioned in checklist only, no dedicated tool
  • Combo Trio — not implemented
  • Compare — not implemented

Strengths

  • Shard / chip calculator is exact: Tier I 2/0, Tier II 4/2, Tier III 6/4, Tier IV 10/8. Default 0 → 40 returns 1,140 / 740.
  • Honest two-currency framing in the checklist (stones → skill XP; per-hero shards + ES chips → 40-level ladder) — directly resolves the live page's biggest economy-copy bug.
  • Step 1 decision tree reframes the eligibility rule into 30 seconds of taps (5★ · Lv. 120 · ES Lv. 5).
  • Hero Swap rules in copy and in the calc match audit verbatim: 100% material conversion, donor keeps 10 unlock-shards, donor resets to 1★ Lv. 1, talents two-way, type-match enforced, swap is free, irreversible.
  • Icon fallback chain prevents broken-image cells even when CDN is slow.

Accuracy issues

  • Stones calc is off-by-one. runCalcStones reads STONE_PULL_BY_LEVEL[lvl - 1], so cur=0, tgt=1 returns 0 stones (real: 75). cur=5, tgt=10 returns 1,800; real is 1,575. Off by 225 on the most common query.
  • Intro says "6 heroes are live" — true for Phase I, but the same audit catalogs 18 total. The 12 queued heroes are never named, which matters for the swap decision.
  • Footer note describes the ladder as "15/15/30/30/45/45/60/80/130 stones across Lv. 1–10" — 9 rungs, not 10 (L10 is free).
  • Decision-tree response says swap is "once per target"; audit canon is "ONCE per player per phase". Dropping "per phase" materially changes long-term planning.
  • Default Calculator 3 state ships BLOCKED — first donor is Air (Abad), first target is Army (Sara); type-mismatch fires before user touches anything.
  • Calc 3 still renders "Lv. X / 40" + an FP gain when type-mismatched — numbers describe a swap that can't legally happen.
  • Honor Wall called out only as a one-liner aside in Step 5, even though it is the single largest missing piece (39,900 stones / hero — ~4× the entire 40-level ladder's stone cost).
  • Modal skill icons load via '../../' + s.icon with no error fallback (unlike portraits) — broken-image risk if assets aren't deployed.

UX issues

  • Hostile gate. "fk boats" 3-button puzzle; wrong answers redirect to passwords.html with the taunt "nope, dummy" after 900 ms. A Start-Here page can't evict its newcomers.
  • Sticky priority strip uses blurred rgba(13,17,23,.92) with no extra parent padding — content scrolls behind it instead of under a hard edge.
  • Calculator 1 has a "Slot 3 (combo)" dropdown that the calc never reads — a dead control.
  • Number inputs silently clamp() overflows on input (typing 45 in a max-40 field blanks the value with no message); on iOS there are no spinners for numeric keyboards.
  • Decision-tree icon glyph for "almost / partial" is a literal tilde — doesn't read as that to a casual player.
  • Progress bar sits above the checklist intro, so first visit reads "0 of 5 steps complete" as a guilt-trip on landing.
  • Awakening-card cadence info ("1 immediately, 5 on a cadence") lives only inside Step 3's checklist row — players who skip ahead to calculators never learn it.
  • Hero modal has no Escape handler and the only close is a tiny × top-right; on phones with 5 skills the description overflows badly.
  • Verdict pill is the most actionable line but gets visually lost in a wall of gold next to the cost cells.
  • Trio partners are listed dots-separated with no Phase II/III badges — even though CSS for htag chips would render them cleanly.
  • Footer link to heroes-awakening.html calls itself "the canonical reference page", undermining the 4-step funnel the player just used.

Verdict

  • Genuinely friendlier on-ramp than the live page; the funnel, checklist, and shard-ladder calculator are sound. But a broken stones calc, default-BLOCKED swap calc, a dead skill-slot field, and a hostile easter-egg gate add up to a Start-Here page that misinforms or evicts the newcomer it's built for.
V4

Visual Hero Cards

Cinematic portrait cards · combo trio gallery · owned-hero localStorage
v4-visual-hero-cards.html · 1,757 lines Open in new tab ↗ View source

Pillar bullets

  • Heavy, cinematic dark theme: portraits desaturate by default, bloom on hover with a conic-burst sweep.
  • Inline expand panel under each card with skill tiles, level slider, live stat readout, tokenized description.
  • Combo trio gallery — anchor lifted between two partner cards, glowing arc connecting them.
  • 4 calculator cards: Stones → Target, Combo Trio planner (with localStorage ownership), Awake 0 → 40, Honor Wall.
  • Gold "true peak +240,000 FP" callout makes the Honor Wall a first-class storyline, not a footnote.

Calculators implemented

  • Stones → Target per skill correct
  • Awake 0 → 40 shard + chip budget correct
  • Honor Wall per sub-track math right, denominator off
  • Combo Trio planner with owned-hero state in localStorage
  • Compare — not implemented
  • Swap vs grind ROI — not implemented as a calculator

Strengths

  • Skill stone ladder is correct: STONE_PER_PULL (15/15/30/30/45/45/60/80/130) and STONE_PER_LEVEL (75/75/150/150/225/225/300/400/650/0) match the audit — the exact value the live page got wrong.
  • Honor Wall is fully surfaced — both a dedicated calculator and a gold "true peak +240,000 FP" callout (39,900 stones full wall, +40,000 FP / hero, +240,000 hero ceiling).
  • 40-level ladder is exact: shardCostForLevel sums to 1,140 / 740 to L40 — fixes the live page's row-40 understatement.
  • Combo trios sourced cleanly from hero.comboTrio with anchor lifted, partners labelled "missing" when not owned, and a buff-token rule pill — all 6 trios match the audit.
  • Ownership persistence works: ownedHeroIds hydrates from hawV4_owned on boot and re-persists on every toggle — the trio planner's COMPLETE / partial / LOCKED status is the calculator-idea-6 the audit asked for.

Accuracy issues

  • Honor Wall sub-track ladder loop sums to 19,850 (50×50 + 50×80 + 50×120 + 49×150) but the "% of full track" calc uses 19,950 as denominator. The page reports a value its own loop can't produce — % never quite hits 100% at L199.
  • Wrong skill description string at L6+. pickDescription prefers descriptionLv2_5 over descriptionLv6_plus for Lv ≥ 6, so the page shows the wrong copy from Lv 6 onward.
  • Phase II/III placeholder card promises an "ultimate kill name" — looks like a typo for ultimateSkillName, but it ships as a factual claim.
  • Trio reorder for visual layout puts Phase II partner on the left and Phase III on the right of the anchor without per-side phase labels — viewer can't tell which is which.
  • Stones → Target Team FP uses inconsistent indices: start reads levelTable[cur], end reads levelTable[tgt-1]. Undercounts the L0 → L10 delta vs the per-level table.
  • Internal table identifiers leak into player copy: "Card item IDs already exist in hero_awakening_batch (44300007–44300018)" and the footer lists internal asset paths. Exactly the "dense, technical buff-ID language" the audit flagged as a failure mode.

UX issues

  • Cinematic awaken is hover-only — the portrait swap, awake-stamp, and conic burst all gate on .hero-card:hover. Touch users never see the central "moment" the toolbar copy advertises.
  • Honor Wall sub-track selector (Track 1 / Track 2) is a dead control — recalcHonor never reads hwTrack.value; both options compute identically.
  • Skill slider min='1' — a player who has not pulled a skill can't model Lv 0 starting state.
  • Slider thumb has no touch-action:none and uses grab/grabbing cursors — fights vertical page scroll on touch.
  • Inline expand panel uses scrollIntoView({block:'center'}) — on phones the panel center is often above the tapped card, hiding it.
  • Trio gallery SVG arc is fixed at viewBox 600 × 260 with preserveAspectRatio='none' — stretches on narrow viewports until it no longer visually connects.
  • Combo card popover is absolutely positioned at left:18 / right:18 / bottom:18 — hovering the rear partner covers the very name plate the player needs.
  • Every card stamps two portrait layers + conic burst + ring SVG — scrolling the grid pegs the GPU on low-end Android.
  • Filter chips have no reset; selecting Army + Phase III strands the user staring at 2 heroes with no other CTA.
  • Header pill "40 lv · 4 skills · 9000 stones/hero" bundles two unrelated cost stories — 9,000 stones is skills only, not the 40-level ladder.
  • Stones calc is Phase-I only but the shard budget calc lists all 18 — the asymmetry is unexplained.

Verdict

  • Visually striking, audit-aware rebuild that finally surfaces the Honor Wall, fixes both numerical lies, and adds genuinely useful calculators. But it leaks table names into player copy, runs a dead Honor Wall sub-track selector, picks the wrong skill description at Lv 6+, and stakes its central cinematic on hover — which simply doesn't exist on the mobile devices most Server 2864 players actually use.
