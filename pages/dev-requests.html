Request 01 · Titan Canyon · Chat and map markers

Battle report spam is flooding the only usable squad channel

Combat-blocking Reuses existing systems

Issue

Titan Canyon squads have two ways to talk to each other, and automatic battle notifications post into both of them.

Alliance Chat is the better channel by a wide margin: sharing a base or an objective there takes a single tap. The Titan Canyon squad channel is the weaker one, because sharing an objective takes several taps and frequently posts to a different channel in the list. During the event, Alliance Chat fills with per-battle notification lines faster than anyone can read, so mid-fight the good channel is unusable.

Background

During SVS this is not a problem. Players coordinating in game use World Chat, which does not receive per-battle notifications. Titan Canyon has no equivalent clean channel, so servers are pushed onto third-party voice applications to run the event at all.

The request

Part 1 · Chat filtering

Add an option to hide Titan Canyon battle notifications in Alliance Chat, and release it with the option enabled by default. The notifications still post into the Titan Canyon squad channel, so nothing is lost.

There is precedent for a default-on change of this kind: the recent increase to font sizes was applied by default rather than read from device accessibility settings. That change also reduced how many messages fit on one screen, which makes the notification flood costlier still.

Part 2 · Squad captains

Allow up to three captains per Titan Canyon squad, roughly one captain per eleven players. Captains, and alliance officers by default, get the map marker ability that already exists in Warzone and Alliance play, usable inside Titan Canyon. This gives squads visible direction on the map for players who cannot watch a chat window continuously during a fight.

Part 3 · Markers, game-wide

This part is about the marker system generally, not only Titan Canyon. When a marker is posted, also post it as a chat message carrying the message text, the marker icon, the coordinates, and the countdown if one was set:

  • Warzone marker→World Chat
  • Alliance marker→Alliance Chat, on the home server
  • Titan Canyon marker→Alliance Chat, while in the Titan Canyon servers

None of the three should be complex to build. All three reuse existing systems, and each part is useful on its own, so any one of them can be adopted without the others.

Request 02 · Enigma Realm · Resource Library

A well still labeled "Rich" can be empty

Defect

Issue

The "Rich Enigma Well" label does not reflect what is left inside the well.

Each well holds a limited number of items, which the panel counts as acquisitions, and two power-up buffs. In the screenshots below, a well is still shown as Rich while both buffs read Emptied, and the panel still reports 2/2 buffs and 5/5 acquisitions remaining. Because the game still counts it as Rich, it will not refresh. The recording shows wells in this state across a single run, including ones that have been fully drained.

Background

This has been present in Enigma Realm for a long time. The recent change that allows solo players into Enigma Realm has made it much more damaging: a solo player can take what they need and leave behind a well that is still shown as Rich. A full five-player team then arrives, finds nothing usable, and cannot supply their squad.

The request

Split the indicator into the two things players actually care about, and make the contents predictable:

  • Increase the item count and make it a fixed amount. 90 crystal shard items per well in the weak Enigma zone, 120 in the strong Enigma zone.
  • Auto-claim to the members in the truck instead of requiring players to tap individual items while under pressure.
  • Base the Rich label on items only. Show Rich when more than five items remain.
  • Add a separate indicator for power-ups and buffs so players can see at a glance whether those are still available or emptied.

Request 03 · Garage · Merge All

Winning a permanent Pop Star base takes away Merge All

Combat-blocking Reuses existing systems

Issue

While the Pop Star base effect is active, Merge All merges level 100 units past 101, directly to level 102, so the number of trained units is divided by four instead of by two.

There is no way to stop at level 101 through the normal flow. The only option is dragging units together by hand: one manual drag per merge, repeated for every unit, at the exact moment a player needs to be fighting. During SVS, UD and Eternal Lands, Merge All becomes a button you cannot press.

Background

The permanent Pop Star base is a reward that removes a capability every other player keeps: producing level 101 units through Merge All.

The request

Make the Merge All dialog aware of the Pop Star effect. The panel is otherwise unchanged.

Today
One button, labeled OK, which does not describe what it does.
Requested · Pop Star active
Two buttons: Merge 101 and Merge 102. The player chooses the maximum merge level.
Requested · Pop Star inactive
A single button, labeled Merge. Same behavior as today, clearer word.

Request 04 · Pop Star event · Rewards

The 30-day Pop Star skin is wasted when it could go to the next player

Fairness Allocation change only

Issue

A player who wins one of the two permanent Pop Star skins in a cycle receives the permanent skin and the 30-day skin.

The 30-day version is redundant the moment it is received. It duplicates the effect the permanent skin already provides, so it gives that player nothing.

The current ladder on our server is: 1st place receives the permanent skin and a 30-day skin, 2nd place receives a 3-day skin, 3rd place receives a 1-day skin, and 4th place receives none. The reward being discarded is the longest-lasting one on the ladder.

The request

When a server player wins a permanent Pop Star skin, pass the skin reward down the server rankings:

  • 1st place's 30-day skin→goes to 2nd place
  • 2nd place's 3-day skin→goes to 3rd place
  • 3rd place's 1-day skin→goes to 4th place, who currently gets none

Why it matters

The fix is a delivery change: send the skin to the next player down instead of to someone who already has it. One line of allocation logic turns a wasted reward into a second player's prize.

Request 05 · Combat marches · Quick Reinforcement

Quick Reinforcement sends Valhallas when players need normal units

Combat-blocking Additive, no change to current behavior

Context

The original request and requirements that became Quick Reinforcement came from this server, so this is a follow-up on the intent behind the feature rather than a new idea.

Issue

The feature was asked for because the unit selection bar is unworkable in combat. Heavy Troopers take up most of the selection window on a mobile device, so filling a march means scrolling a long horizontal list under time pressure. Quick Reinforcement was meant to fill a preset march with the right units in one action.

As shipped, it prioritizes Valhalla units. A player who wants normal units has to deselect the Valhalla slots, scroll sideways through the bar, and select units by hand, which is the original problem, with one extra step added. Units also drop to lower levels during battle, so the bar keeps getting longer while you are fighting.

Outside Titan Canyon, most players most of the time need normal units reinforced, not Valhallas. The shipped behavior serves the exception and leaves the common case doing manual work.

The request

Part 1 · Immediate fix

Add a second button. Keep Quick Reinforce Valhallas exactly as it behaves today, prioritizing Valhalla units and filling with the highest level after that, and place Quick Reinforce Normal beside it. Because current behavior is untouched, there is no risk to players who rely on the feature as it stands. The layout fits on both mobile and desktop.

Today
One button, which always prioritizes Valhallas.
Requested
Two buttons. The left one behaves exactly as it does now.
Part 2 · Follow-up fix

Combat presets already carry a unit type indicator. The player is setting an Army, Navy or Air Force icon on the march, so group units by that type before grouping by level, and the right units appear first instead of after a long scroll. If no unit type icon is set, keep the existing default order. This association already exists on gathering presets; it is missing on combat presets.

Evidence

Related note on Odinium

Separate from this request

Recent events have required Odinium again and again with no reduction in cost. As a result, players now use Valhalla units only in non-PvP events such as alliance truck competitions and World Boss, and in Titan Canyon.

Adding 1,000 Odinium as an option on Truck Heist would help, as would rebalancing rewards so corn, oil and Odinium are treated roughly equally at the existing exchange rates. SVS Warzone reward boxes are one example of where that could apply.

Request 06 · Repair Factory · Deletion

Deleting Valhallas from the Repair Factory has to be done slowly and in one direction

Combat-blocking Defect

Issue

Removing Valhalla units from the normal Repair Factory requires roughly a one second pause between deletions, and has to be done front to back.

Working back to front makes the processing delay much worse and eventually errors out. Clearing a bay is a slow, ordered sequence that cannot be rushed.

Players are doing this because they have run out of Odinium to repair the Valhallas. Those damaged Valhallas have to be cleared out of the normal Repair Factory, because leaving them there causes a larger number of level demotions among normal, non-Valhalla units. So the clearing happens mid-fight, and it is not optional.

The request

Remove the enforced delay between deletions and the front-to-back ordering requirement, so a bay can be cleared at the speed the player taps.

Relationship to request 05

This slow deletion is part of why request 05 matters so much in real combat. Recovering from Valhallas being where the player did not want them is expensive, so it is important they are not sent by default in the first place.

Request 07 · Gathering · Quick Deploy

Quick Deploy sends too many units at facilities

Quality of life

Issue

Quick Deploy is well optimized and is still the best option for gathering marches. The two cases it handles are not consistent with each other.

  • At a resource tile→the march is automatically shrunk to fit the remaining capacity
  • At a facility→the right heroes are picked, then every unit is deployed regardless of time left

The request

Give facilities the same automatic sizing, based on the time remaining in the building rather than on capacity.

Priority

This is a quality of life improvement, not a significant game impact issue. It belongs below the combat items above.

Request 08 · Finance Center · Decor Store and showcase

Decor Material is worth far less to an established account

Fairness

Issue

The Special Weekly Pass grants Decor Material to spend in the Decor Store, but most of the store's stock is only worth buying if you missed a collaboration decoration.

That makes the same purchase substantially less valuable to a long-standing account than to a newer one. A player who already collected the collaboration decorations has little to spend the material on.

Example

Volt Wraith is sold in the Decor Store and grants March Size, the same benefit the Megatron Statue already provides. A player who owns the Megatron Statue gains nothing from buying it, so for that player the material cannot buy march size at all.

Same benefitMarch Size

The request

Part 1 · Decor Store stock

Allow generic decorations to be used to upgrade collaboration decorations, and stock generic decorations in the Decor Store. That gives the store a baseline value that is the same for every account.

Part 2 · Showcase slots

In the Collaboration Decoration showcase, allow generic decorations to be placed in the same slots when no collaboration decoration is present. If that needs another page in the showcase, add one.

Request 09 · Capital · National War Readiness

Every server buff activation depends on two players

Server operations Permission change only

Issue

Only the Server Leader and the Staff Officer can spend gems to activate the capital's National War Readiness buffs.

That is two people for an entire server, and the buffs are activated repeatedly across every event. The result is a constant, avoidable load on two players, and no buff can be activated while both are offline.

Background

Activating a buff spends the activating player's own gems, applies a benefit to the whole server, and can be activated again afterwards. The restriction prevents no abuse; it only limits when the buffs can be activated.

The request

Remove the restriction entirely. If that is not acceptable, extend the ability to spend gems and activate these buffs to all appointed officers in the capital.

Today
Leader and Staff Officer only. Every other appointed officer is locked out.
Requested
Every appointed capital officer can activate, using their own gems.

What happens next

These nine came out of one cycle of play on a single server. We kept the ones with a specific fix attached and dropped the ones that were just complaints. Four interfere directly with combat, and most reuse systems the game already ships.

We are happy to test any of it, provide more recordings, or answer questions about how these situations come up in play. Thank you for reading.
